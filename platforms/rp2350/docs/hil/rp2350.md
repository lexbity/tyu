# RP2350 HIL Evidence

Manual hardware-in-the-loop validation for the RP2350 pack is recorded here.
This pack is treated as a custom board variant forked from the generic ARM and
RISC-V runtime implementations.

## Status

**Not yet run.** The `[test]` rung is `hardware` because QEMU has no RP2350
machine model; until a transcript is recorded below, the pack's hardware
claims are unverified by automation and this file is the placeholder the
manifest points at.

What a recorded run must cover (the board-facing surface this pack claims):

1. **Boot**: a `tyu build --mode=static --platform=rp2350 --isa=<arch>` image
   loads via `picotool load -f -x` and boots from flash on both ISAs — this
   exercises the PICOBIN block (image_def) and the ENTRY_POINT PC/SP.
2. **Diag**: the UART0 `V`/`D`/`H` records decode with `harness-core` at
   115200 baud after the clock bring-up (the baud table assumes the 150 MHz
   `clk_peri` the runtime configures).
3. **Capability words**: `platform.gpio.*` on a real pin (SIO + PADS +
   IO_BANK0 funcsel), `platform.time.now_us` monotonicity across the 1 µs
   TIMER0 tick, `testio.write-*`.
4. **Region allocator**: `region_smoke`-equivalent create/alloc/store/load/
   destroy on hardware, and the `REGION_EXHAUSTED` (26) trap on exhaustion.
5. **Trap path**: an intentional trap emits a well-formed D record with the
   faulting PC (exception-frame extraction on Arm, mtvec entry on RISC-V).
